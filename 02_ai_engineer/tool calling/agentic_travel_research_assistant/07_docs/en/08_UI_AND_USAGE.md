# UI and usage

This chapter documents practical operation of the project, the Streamlit interface, custom questions, presets and local history behavior.

## 1. Startup

On Windows use `SETUP_AND_START_UI.bat` for first setup. It installs only missing/incompatible dependencies and retrains only when the model is missing or stale. Use `RUN_UI.bat` for normal daily startup.

## 2. UI tabs

- **Chat**: custom question or preset.
- **Tool Explorer**: manually exercise a single tool through forms.
- **Data Quality**: quality gates and dataset diversity.
- **Train & Evaluate**: training and benchmark workflows.
- **Live Statistics**: persistent SQLite-backed usage analytics.
- **Project Statistics**: an interactive Plotly dashboard for repository, data, routing, model and benchmark statistics, plus a static plot gallery.
- **Dataset Explorer**: inspect CSV datasets.

## 3. Custom questions

The Chat box accepts free text. Good requests specify destination, duration, budget and preferences where relevant. Example: “I am going to Rome for 4 days. Check the weather, find hotels below EUR 180/night and suggest Italian restaurants under EUR 40/person.”

## 4. Presets

The UI includes 30 scenarios × 2 languages. They are more than demo buttons: they also form a regression catalogue validated by `08_validate_presets.py`.

## 5. Usage history

Chat runs are stored locally in `06_results/usage/usage_history.sqlite3`. The database is Git-ignored and can be cleared or exported as CSV from the UI.

## 6. Privacy

Local usage analytics does not itself send questions to an external analytics service. When using `openai_direct` or live providers, request data required by those external services is naturally transmitted to them.

## 7. Interactive Project Statistics dashboard

From v1.6 onward, Project Statistics is Plotly-based, so charts support hover details, zoom, legend toggling and dynamic controls. The dashboard is split into six views:

1. **Overview** — core KPIs, dataset scale, methodology radar and quality/latency trade-off.
2. **Data & diversity** — linguistic and entity diversity, interactive price histograms and category distributions.
3. **Routing & benchmark** — intent balance, multi-intent complexity, benchmark workflow complexity and expected tool distribution.
4. **Model & methods** — per-intent precision/recall/F1, selectable methodology metric, radar comparison and latency trade-off.
5. **Saved plots** — gallery of reproducible static snapshots from `06_results/project_statistics/*.png`.
6. **Data tables** — view and download the CSVs behind the charts.

Interactive views are built from the same CSV/JSON artifacts generated by `04_scripts/09_generate_project_statistics.py`; the dashboard therefore does not rely on hidden or manually entered values. Price histograms expose dataset and bin controls, category charts support Top-N filtering, and the methodology view lets the user select either quality or latency metrics.

## Conclusion

The UI is the primary human interface. CLI entry points remain available for reproducibility, automation and testing.


## Data Quality dashboard (v1.7)

From v1.7 onward, Data Quality follows the same interactive Plotly dashboard approach as Project Statistics. Separate views cover quality gates, query-corpus diversity, entity-name diversity, train/validation/test leakage, router label balance, and persisted audit snapshots.

Main interactive elements include:

- quality-gate gauge and gate-status chart;
- query scale-vs-diversity bubble chart;
- query repetition-risk chart;
- entity unique-name and skeleton-diversity chart;
- split-leakage heatmap;
- router intent-label balance;
- selectable Top-N normalized-query-pattern explorer;
- saved PNG audit gallery and downloadable JSON/CSV reports.

The full audit is still not executed at every UI startup. It only needs to run after data changes or on explicit user request.

## Live Statistics dashboard (v1.7)

Live Statistics now builds an interactive dashboard from the local SQLite usage history. Overview, Trends, Tools, Behavior, and History & export views separate operational usage concerns.

The dashboard includes:

- question and tool-call trends;
- run-success and latency trends;
- P50/P95 latency;
- tool usage and tool success rate;
- tool-latency box plots;
- most common tool sequences;
- methodology quality-vs-latency;
- top-destination treemap;
- weekday × hour usage heatmap;
- question-length vs end-to-end-latency scatter;
- language / data-mode / custom-vs-preset distributions;
- tool error breakdown;
- exportable and clearable local history.

Every Plotly chart uses an explicit unique Streamlit key and the current `width="stretch"` API.


## Shared Light/Dark chart theme and consistent height (v1.8)

The sidebar **Analytics chart theme** control provides two high-contrast modes: `Light` and `Dark`. The selection applies to interactive Plotly charts across Project Statistics, Data Quality and Live Statistics. Light mode uses white chart surfaces with black text; Dark mode uses dark chart surfaces with white text. Primary dashboard charts share a 460 px height so side-by-side cards stay visually aligned.
